# 生态统计方法专项规范

## 生态学代码必须有“矩阵方向意识”

这是本 Skill v2.0 的重点规则。

### 明确矩阵结构

典型群落数据应说明：

```r
# spe：行 = 样本，列 = 物种/OTU/ASV
# env：行 = 样本，列 = 环境因子
```

不要默认所有生态包都接受同一方向的数据。

---

### 多个矩阵先对齐样本

```r
# 注意：群落矩阵和环境矩阵必须对应同一批样本，且行顺序一致
common_samples <- intersect(
  rownames(spe),
  rownames(env)
)

spe <- spe[common_samples, , drop = FALSE]
env <- env[common_samples, , drop = FALSE]

stopifnot(identical(rownames(spe), rownames(env)))
```

如果原论文代码没有做显式对齐，并且任务是“严格复现”，不要擅自改变原逻辑；可用注释提醒用户自行确认顺序。

---

### 不能只看维度相等

两个数据框都有 30 行，不代表样本一定对应。

优先检查样本名，而不是只写：

```r
nrow(spe) == nrow(env)
```

---

## 相关分析：先选方法，再写 `cor()`

### Pearson

适合分析线性关系，通常要求连续变量且对异常值敏感。

不要仅凭“数据正态”三个字机械选择。

---

### Spearman

用于单调关系、秩数据或明显不适合 Pearson 的场景。

---

### 不得为了显著性切换方法

绝不能写出这样的隐含逻辑：

> Pearson 不显著，换 Spearman 试试。

方法选择应由数据性质和研究问题决定。

---

### 缺失值处理参数必须说清楚

```r
corr <- cor(
  df,
  method = "pearson",
  use = "pairwise.complete.obs"
)
```

注释：

```r
# pairwise.complete.obs 会让不同变量对使用不同的有效样本量
```

## 多重检验与显著性星号

### 不擅自加入校正

如果用户原分析用原始 P 值，不得为了“规范”直接替换成 BH。

---

### 使用校正值时名称必须明确

```r
result$p_adj <- p.adjust(
  result$p_value,
  method = "BH"
)
```

显著性星号若基于 `p_adj`，必须写清：

```r
result$sig <- dplyr::case_when(
  result$p_adj < 0.001 ~ "***",
  result$p_adj < 0.01  ~ "**",
  result$p_adj < 0.05  ~ "*",
  TRUE                 ~ "ns"
)
```

不能图里写“P value”但实际用的是 `p_adj`。

## 方差分析、重复测量和混合模型

不能看到 `Treatment` 和 `Time` 就自动使用普通两因素 ANOVA。

必须先判断：

- 是否为同一实验单元随时间重复测量。
- Replicate 是否是真实独立重复。
- 是否有区组、样地、研究或个体随机效应。

如果同一个样本重复测量，普通 ANOVA 的独立性假设可能不成立。

代码注释应明确随机效应含义，例如：

```r
# (1 | Replicate) 表示不同重复允许拥有不同的随机截距
model <- lme4::lmer(
  Value ~ Time + (1 | Replicate),
  data = df
)
```

不要把随机效应写成一句“控制误差”。

### 先写清"为什么用混合模型"

在模型前用一两句话说明非独立性从哪来，例如：

```r
# 为什么用混合模型：同一样地在 3 个时间点重复采样，同一样地内的观测不是相互独立的。
# 普通 ANOVA/线性回归假设残差相互独立，这里不满足，所以把样地作为随机效应。
```

### 拟合之后要做诊断

拟合完不能直接看 P 值。至少检查残差，并告诉用户怎么判断：

```r
# 残差诊断：残差与拟合值之间不应有明显的规律（如漏斗形、弯曲）
performance::check_model(model)

# 广义线性混合模型（计数、二项等）用模拟残差更可靠
# 如未安装：install.packages("DHARMa")
sim_res <- DHARMa::simulateResiduals(model)
plot(sim_res)
```

- 计数数据过度离散或零值很多、需要时间自相关结构时，可考虑 `glmmTMB`（支持负二项、零膨胀、`ar1()` 等）。换模型属于方法改变，要先和用户说明。
- 报告解释度时区分边际 R²（只含固定效应）和条件 R²（固定 + 随机效应），用 `performance::r2()` 或 `MuMIn::r.squaredGLMM()`，并写明用的是哪一个。
- 事后两两比较用 `emmeans::emmeans()`，写明校正方法（如 Tukey）。
- 画模型结果时，用模型预测值和置信区间（如 `ggeffects::ggpredict()`），并注明预测值是在其他变量取什么水平时得到的；不要对原始散点直接画一条 `geom_smooth(method = "lm")` 冒充模型结果。

---

### 多个变量批量做方差分析

土壤、农学论文常要对十几个指标逐个做方差分析并标显著性字母。批量处理没问题，但下面几点必须写进代码：

1. **每个变量分别检查前提**（残差正态性、方差齐性），把检查结果和方差分析结果一起导出；不满足时给出备选（如 Kruskal-Wallis 加 Dunn 检验），而不是默默照用 ANOVA。
2. **分清两种多重比较**：同一变量内各处理两两比较的校正（Tukey、LSD、Duncan 等），和跨多个变量同时检验时是否再做校正（如 FDR）。两者都要在注释里写明。
3. **方法要写清楚**：LSD 和 Duncan 法对 I 类错误控制较宽松，用户没指定时优先用 Tukey；用户或原文指定了就照用，并在注释里说明。
4. 导出表格包含均值、标准误、样本量和字母，不只给字母。
5. 循环里每个变量的结果要能追溯，出错时知道是哪个变量。

## PCA、PCoA、NMDS：不能混用

### PCA

- 基于变量协方差/相关结构。
- 通常作用于样本 × 连续变量矩阵。
- 不等同于基于 Bray-Curtis 的 PCoA。

### PCoA

- 基于距离/相异度矩阵。
- 距离选择会改变结果。

### NMDS

- 基于距离排序。
- 结果解释应关注 stress 和相对距离。
- 轴本身不像 PCA 那样具有固定方差解释含义。

AI 不得把三个方法都称为“主成分分析”。

---

## RDA / CCA：代码前先明确响应矩阵与解释矩阵

```r
# spe：群落响应矩阵
# env：环境解释变量
```

模型示例：

```r
rda_model <- vegan::rda(
  spe_hel ~ pH + SOC + TN,
  data = env
)
```

#### 注意事项

- 不自动 log 所有环境变量。
- 不自动 Hellinger 所有群落矩阵。
- 不因 RDA 图“看起来更好”而替换 CCA。
- DCA 梯度长度只能作为方法决策的一部分，不能机械套用“>4 用 CCA，<3 用 RDA”而忽视原研究设计。
- 若进行变量筛选或 permutation test，要明确这是额外步骤。
- 用 `ordiR2step()` 前向选择时：先检查共线性（如 `vegan::vif.cca()`），以校正 R² 作为停止准则；并提醒筛选后报告的 P 值偏乐观。

#### 提取坐标时写清对象，并写明 scaling

vegan 2.7 起不能再用 `summary(rda_model)$sites` 这类写法取排序得分，会直接报错；应统一用 `scores()`。`scaling` 决定图怎么解读，必须写出来，不能依赖默认值：

```r
# scaling = 2：物种/响应变量之间、响应变量与解释变量之间的夹角可解读为相关关系（vegan 默认）
# scaling = 1：样本之间的距离近似保持原距离，适合看样本分布
# ★ 如需与原论文一致，按原文选择 scaling
SCALING <- 2

site_scores <- as.data.frame(
  vegan::scores(rda_model, display = "sites", choices = 1:2, scaling = SCALING)
)

species_scores <- as.data.frame(
  vegan::scores(rda_model, display = "species", choices = 1:2, scaling = SCALING)
)

biplot_scores <- as.data.frame(
  vegan::scores(rda_model, display = "bp", choices = 1:2, scaling = SCALING)
)
```

对应注释：

```r
# site_scores：样本在排序空间中的位置
# species_scores：响应变量/物种的排序坐标
# biplot_scores：环境解释变量箭头的坐标（display = "bp"）
```

轴解释率用 `summary(vegan::eigenvals(rda_model))` 计算，并说明是占总惯量还是占约束惯量的比例；调整后的总解释率用 `vegan::RsquareAdj(rda_model)`。

需要显著性时，单独写置换检验，并说明检验的是什么：

```r
# 整体模型检验
anova(rda_model, permutations = 999)

# 逐个解释变量的检验
# 注意：by = "terms" 是按公式顺序的序贯检验，变量顺序会影响结果；
#       by = "margin" 是控制其他变量后的边际检验，两者不能混着解释
anova(rda_model, by = "margin", permutations = 999)
```

## PERMANOVA / adonis2：显著不等于“组中心一定不同”

典型流程应考虑：

1. 距离选择。
2. PERMANOVA。
3. 必要时检查组内离散度。
4. 若有重复测量/区组，考虑限制置换。

示例：

```r
permanova <- vegan::adonis2(
  spe ~ Group,
  data = metadata,
  method = "bray",
  by = "terms",       # 注意：vegan 2.6-8 起默认 by = NULL，只给整体检验；需要逐项结果必须写明
  permutations = 999
)
```

`by` 的选择要和研究问题对应，且要写进注释：

- `by = NULL`：整个模型一起检验（新版默认）。
- `by = "terms"`：按公式顺序逐项检验，**变量顺序会影响结果**。
- `by = "margin"`：每一项在控制其他项后的边际检验。

复现旧论文时，原文如果是旧版 vegan 跑的 `adonis2()`，当时默认是逐项检验，复现时要显式写 `by = "terms"` 才能对上。旧的 `adonis()` 已在 vegan 2.7 中停用，遇到旧代码要改成 `adonis2()`，并说明这一改动。

有区组、重复测量或嵌套设计时，用 `permute::how()` 限制置换，例如：

```r
# 注意：同一 Block 内的样本只在 Block 内部互换，避免把区组差异当成处理效应
perm_design <- permute::how(nperm = 999, blocks = metadata$Block)

permanova <- vegan::adonis2(
  spe ~ Group,
  data = metadata,
  method = "bray",
  by = "terms",
  permutations = perm_design
)
```

若研究结论依赖组间差异，建议提醒：

```r
# 注意：PERMANOVA 显著可能同时受到组中心差异和组内离散度差异影响
# 如需严格区分，应进一步检查 betadisper()
```

不要自动替用户添加 `betadisper()` 并改变其原始论文复现流程；可以作为诊断或补充模块。

## 微生物组与群落数据：哪些是要写明的"决定"

下面这些步骤会改变结果，必须由用户或原文决定，代码里写明做了什么、为什么做，不能默认执行：

- 16S/ITS 数据预处理：去除叶绿体和线粒体序列、稀释（rarefy）或其他标准化、低丰度过滤的阈值。
- 功能预测（PICRUSt2、Tax4Fun2、FUNGuild 等）得到的是**推断的**功能，不是实测，结果表述要写"预测的"。
- 群落构建（中性模型、βNTI/RC、iCAMP 等）：不同方法前提不同，不要凭单一指数下"随机过程占主导"之类的结论。
- 复刻 STAMP 等软件的结果时，先确认检验方法和校正方式一致，再说"结果一致"。

---

## Mantel / Partial Mantel：先确认输入是距离矩阵

不要把两个普通变量直接塞进 Mantel test。

应明确：

```r
# Mantel 检验比较的是两个距离/相异度矩阵之间的关联
```

如果环境数据还是原始变量矩阵，必须先明确采用什么距离。

Partial Mantel 的控制矩阵也必须具有对应样本结构。

不得把 Mantel 相关解释为因果效应。

---

## VPA / variation partitioning / 层次分割

当用户使用 `varpart()`、`rdacca.hp` 或类似方法时：

- 说明“独立解释”“共同解释”“总解释”不是同一个概念。
- 负的调整解释率不能简单当作“负贡献”。
- 不把层次分割的重要性直接当作回归系数。
- 如果原方法基于 adjusted R²，就不能改成 raw R²。

结果图中必须保持统计量名称一致。

### 几类"变量重要性"各回答什么问题

用户说"看哪个因子最重要"时，先弄清用的是哪一类方法，结果的说法不能混用：

| 方法 | 回答的问题 | 常见写法 | 要提醒的点 |
|---|---|---|---|
| 随机森林置换重要性 | 打乱这个变量后，模型预测变差多少 | `randomForest(importance = TRUE)`；显著性用 `rfPermute` | 是"对预测的贡献"，不是效应大小；高度相关的变量会互相分摊重要性 |
| 混合模型的层次分割 | 各固定效应对边际 R² 的贡献 | `glmm.hp`（基于 `MuMIn::r.squaredGLMM()` 的边际 R²） | 需先建好混合模型；只分解固定效应解释的部分 |
| 排序模型的层次分割 | 各解释变量（组）对 RDA/CCA 校正解释率的贡献 | `rdacca.hp` | 依据校正 R²，与原文一致，不能换成未校正的 |
| 变差分解 | 几组变量各自独立解释与共同解释多少 | `vegan::varpart()` | "共同解释"不是交互效应；校正解释率可以为负，不能当作"负贡献" |

无论哪一种，都不写成"X 导致 Y""X 的效应最大"。

---

## 随机森林：必须区分拟合度、预测性能和变量重要性

### 不把变量重要性写成因果效应

`%IncMSE` 高说明该变量对当前森林预测精度的重要性更高，不等于“该变量导致因变量变化”。

---

### 模型解释度不自动等于泛化预测能力

训练内 `R²`、OOB 误差、交叉验证性能、独立测试集性能不是同一个指标。

如果用户问“加入 D 后解释度从 30% 到 50%，能不能说预测性能提高”，代码/解释必须先看这个 30%/50% 到底来自哪里。

---

### rfPermute / permutation importance

若用户用置换检验给变量重要性做 P 值：

- 保留原 `nrep`。
- 不擅自把原 P 改成 BH。
- 星号必须与使用的 P 值一致。

---

### 设置随机种子

新建随机分析时建议：

```r
# 固定随机种子，便于重复运行得到一致的随机过程
set.seed(123)
```

已有代码则保留原 seed。

---

### 先筛变量再检验：要提醒选择偏倚

用户想"先用随机森林筛选重要变量，再用这几个变量做线性回归看显著性"时：用同一份数据先筛选、再检验，P 值会偏乐观（选择偏倚）。不要默认这样做；用户坚持时照做，但在代码注释里写明这一局限，并建议用嵌套交叉验证或独立数据检验。

---

### 树模型的评估与 SHAP 解释

随机森林、XGBoost 等树模型要报告预测性能，不能只给重要性图：

- 回归报告交叉验证或独立测试集上的 R²、RMSE；分类报告准确率，并与无信息率（NIR）比较，同时给 Kappa 或 AUC。
- 调参和评估要用不同的数据划分，避免信息泄漏。
- 用 SHAP（如 `shapviz`、`kernelshap`、`fastshap`）解释模型时说明：SHAP 解释的是**模型怎么用这个变量做预测**，不是因果效应；高度相关的变量之间贡献会互相分摊。
- 这类包更新较快，函数名和参数先核对用户安装的版本。

---

## PLS-DA / OPLS-DA：监督模型必须提醒过拟合

代码必须让用户知道：

- PCA 是无监督探索。
- PLS-DA / OPLS-DA 使用分组信息，是监督模型。
- R²Y 较高不自动证明模型能预测新样本。
- Q²、交叉验证、置换检验、独立测试集分别回答不同问题。

如果只是用全部样本展示组间分离，可以写：

```r
# 当前模型主要用于描述已有样本的分类结构
# 如果目标是评价未知样本预测性能，还需要独立测试或严格交叉验证
```

## 结构方程模型 / piecewiseSEM

不能只给 `psem()` 然后画箭头。

至少应注意：

1. 每个子模型对应什么生态关系。
2. 响应变量是否重复出现在不合理位置。
3. 随机效应结构是否与实验设计一致。
4. 路径系数是标准化还是原始尺度。
5. Fisher's C / d-sep 等整体检验含义。
6. 图形中的显著路径与实际模型输出一致。

如果用户给原论文结构，不能为了模型更显著擅自删路径。

### piecewiseSEM 还是 lavaan

- **piecewiseSEM**：逐个子模型分别估计，子模型可以是混合模型、广义线性模型，适合有随机效应、非正态响应的生态数据；整体拟合看 Fisher's C 和 d-sep 检验。
- **lavaan**：整体协方差结构估计，适合有潜变量、需要 CFI、RMSEA 等全局拟合指标的情形。

按研究设计选，不要因为哪个"更显著"而换。

### 还要提醒的几点

- **样本量**：自由参数相对样本量过多时，估计不稳定。样本少时路径要精简，并在注释里提醒。
- **交互项和非线性路径**：先要有生物学依据，再比较加与不加的模型（如 AIC），不能为了"创新"硬加。
- **分类外生变量**（如处理、生态系统类型）：说明它是以虚拟变量进入模型，还是做多组分析（piecewiseSEM 的 `multigroup()`），两者回答的问题不同。
- **结果怎么看**：Fisher's C 的 P > 0.05 表示数据没有拒绝这个模型结构，不等于证明了因果机制；d-sep 检验显著，说明可能漏了路径；标准化系数用于比较路径相对强弱，要写明标准化方法。
- AI 生成的 SEM 代码必须实际运行，并逐条核对路径与输出一致。示例 `examples/piecewise_sem_example.R` 可作参照。

## Meta 分析、效应量和机器学习的组合

### Meta 分析本身

- **效应量类型**要和数据对应：对数响应比（lnRR）适合比例变化、正值数据；标准化均值差（SMD/Hedges' g）适合不同量纲；相关系数用 Fisher's z。用 `metafor::escalc()` 计算，并在注释里写明公式依据。
- **同一研究多个效应量不独立**：用多层模型 `metafor::rma.mv()`，随机效应写明层级（如 `~ 1 | Study/ES_ID`）。
- **异质性**：报告 Q 检验、I²、τ²，并说明 I² 的含义。
- **发表偏倚**：漏斗图、Egger 类回归检验（如 `regtest()`，多层模型需改用适合的方法），并说明其局限。
- **原始数据录入要先核对**：SD、SE、n 缺失或混用时，处理方式（换算、插补或剔除）要透明，并写进注释。批量计算效应量前，先抽查几行和原文对照。

### Meta 数据再做回归或机器学习

如果用户将 meta 数据进一步做回归或随机森林：

- 先确认输入是效应量、原始值还是研究层级汇总值。
- 研究间非独立性不能因为进入随机森林就自动消失。
- 插补方法、研究权重和随机森林变量重要性是不同层次的问题。
- “随机森林插补”不是“多重插补”的同义词。

代码注释应避免模糊表述。
