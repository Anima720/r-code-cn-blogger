# 风格来源：中文科研公众号画像

本文件记录 Skill 的写法从哪些公众号提炼而来、吸收了什么、避开了什么。它用于理解风格取向，**不是要求模仿任何作者的文字或口吻**，也不能据此对用户声称"某号常用某方法"。

## 证据来源与局限

- v2.0（2025）：基于当时公开可检索的教程内容，归纳了 7 个号的稳定写法。
- v3.0（2026-10）：通过搜狗微信搜索，重新检索了这 7 个号及新增的 4 个号。微信原文链接会跳转到反爬验证页，无法批量读取，所以**这一轮只看到了推文标题和截断的摘要，没有读到正文，也无法核实发布日期**。
- 因此，下文"可吸收"一栏写的是**写法倾向**，大多来自标题和摘要的可见信号，再用统计常识补足成规则。凡是基于常识补充、而不是来自账号本身的内容，都在条目里写明。
- 地上地下生态学这次没有检索到，暂不提炼。检索中出现的"边际生态学""地下生态学PKU"是别的号，也没有混用。
- 以后如能拿到各号推文的链接、PDF 或截图，应以正文为准，逐条修订本文件。

## 各账号画像

### 生态R学社：方法落地 + 生态矩阵意识

**可吸收**

- 从生态学问题或论文方法直接过渡到 R 实现。
- 明确区分物种/OTU/ASV 矩阵、环境因子矩阵和分组信息。
- Hellinger、log、标准化、距离矩阵等预处理就地说明目的。
- 关键步骤（`rda()`、`vegdist()`、`adonis2()` 等）直接标注统计含义；提取 sites、species、biplot 时说明对象代表什么。
- 变量重要性不只有随机森林：混合模型用 glmm.hp 做边际 R² 分解，RDA/CCA 用层次分割。
- 混合模型出图用 ggeffects 取模型预测值和置信区间，而不是对原始散点画一条拟合线，做到"图和模型一致"。
- SEM 同时给 piecewiseSEM 与 lavaan 的对照，讨论分类外生变量怎么进入模型。
- 字体、轴顺序、长宽数据转换等常见需求单独讲清。

**要避开**

- 因为生态教程常见 Hellinger 转换，就在用户没要求时自动加入。
- 标题党和营销话术；"回复关键词领代码"式的残缺代码；"一学就会""几乎解决所有问题"之类的绝对化说法。

**证据强度**：弱。

### 清同趣科研：完整流程 + 多种展示

**可吸收**

- 先说方法是什么、适合什么问题，再进入代码。
- 预处理、正式统计、结果提取、绘图、保存形成完整链条，复杂分析拆成小步骤。
- RDA 讲到变量筛选（如 `ordiR2step()` 前向选择），而不是把全部环境因子直接放进模型。按统计常识补充：前向选择要先检查共线性、以校正 R² 作停止准则，并提醒筛选后的 P 值偏乐观。
- 图保存为 PDF 等矢量格式；复刻论文图时点名期刊和图号，便于对照。

**要避开**

- "绝美""Nature 同款""有手就行"一类形容词堆叠。
- "一比一复刻"只追求形似，不交代统计检验和结果解读。
- 用 Illustrator 等软件收尾美化，让最终图脱离代码、无法复现。确需外部软件时要明确告知，并保留可由代码重现的版本。
- 用户只要一张图时，不主动给一堆样式变体。

**证据强度**：弱。

### Datasphere探索：统计前提 + 参数解释 + 易错点

**可吸收**

- 代码前讲清 Pearson、Spearman、Kendall 等方法的适用条件。
- 关键函数讲决定结果的参数，如 `method`、`use`、`sig.level`。
- 遇到缺失值、不等长变量、长宽转换等问题主动提醒；汇总重复项后再转宽表，避免产生列表列。
- 随机森林同时报告解释量、变量重要性和显著性，并用交叉验证评估；分类模型的准确率要和无信息率（NIR）比较，并报告 Kappa。
- 示例用 `set.seed()` 加模拟数据或内置数据，保证脚本自包含可运行。

**要避开**

- 多个语句用 `;` 挤在一行；用 `T`/`F` 代替 `TRUE`/`FALSE`。
- 多试几个方法、挑显著的那个。
- 让 AI 直接生成 SEM 代码却不运行、不核对拟合指标。

**证据强度**：弱。

### 小白鱼的生统笔记：先理解模型，再看代码

**可吸收**

- 先区分概念：PCA、PLS-DA、OPLS-DA 分别是什么。
- 先讲"数据类型 → 合适模型"：比例数据用 beta 回归，二分类用 logistic，计数用 GLM，非线性用 GAM。
- 讲清数据对象结构（X 矩阵、Y 分组、样本和变量元数据），以及模型输出里能提取什么。
- R²、Q²、VIP、score、loading 给出最基本的解释；区分"解释当前数据"和"预测未知样本"。
- PERMANOVA 配套检验组内离散度（PERMDISP / `betadisper()`）；有混杂协变量时考虑校正后再排序。
- 多重比较同时给参数和非参数方案，并写明 P 值校正。
- 16S 数据预处理的每一步（去叶绿体和线粒体、稀释或均一化、低丰度过滤）都是要在方法里写明的决定。
- 群落构建多方法并用，并交代各自前提。

**要避开**

- 用单一群落构建指数得出"随机性占主导"之类的因果结论。

**证据强度**：弱到中。

### R语言生态小白：零基础可运行

**可吸收**

- 假设读者懂科研问题但不太会编程，尽快给出能跑通的最小完整流程。
- 用教材或公开数据作示例（如 vegan 自带的 `varespec`、`dune`、`BCI`），无需外部文件也能运行。
- 讲清从排序对象提取得分、再交给 ggplot2 的那一步，这是初学者最容易断的地方。

**要避开**

- 为了短而省掉决定结果含义的关键说明。"零基础友好"不等于降低统计要求。

**证据强度**：很弱。可见内容太少，不作为修改规范的主要依据。

### 藻类生态学与R分析作图：群落数据 + 作图导向

**可吸收**

- 对群落数据、环境数据、样点信息的矩阵方向保持敏感，作图参数让用户能直接改。
- 统计结果与图形展示分开组织，作图不能替代分析。
- SEM 加交互项或非线性路径之前，要有生物学依据，并比较模型优劣；样本量相对于参数个数要够。
- 同一样区的多个"重复"是否独立要先问清，必要时考虑随机效应或空间结构，避免伪重复。
- 多功能性分析交代均值法与多阈值法的差别。
- 机器学习要同时给出模型评价，不能只给重要性图。

**要避开**

- 标题与内容不符；"重磅"一类措辞。
- 把功能预测（FUNGuild、Tax4Fun2、PICRUSt 等）当作实测功能。它们是推断。

**证据强度**：弱到中。v2 时就因原文检索困难而没有杜撰其独有习惯，v3 仍坚持这一点。

### 植物功能生态：论文复现 + 功能生态问题导向

**可吸收**

- 方法与生态问题绑定，例如变差分解、层次分割、功能性状关系、森林图、Meta 分析。
- 复现论文图时保留原文的变量定义、标准化方式、模型和筛选逻辑。
- GLMM 先看残差与预测值的关系，有系统性规律就说明模型设定有问题。
- 变差分解中的"共同解释"不是交互效应；校正后的解释率可以为负。
- 重复测量的时间序列要检查时间自相关。

**要避开**

- 把"漂亮图"和"统计推断"混为一谈；为了复杂而复杂。

**证据强度**：弱到中。可见摘要里直接出现了模型诊断和解释上的提醒，参考价值较高。

### 二傻统计（v3.0 新增）：从统计假设讲起

**可吸收**

- 从统计假设切入引出方法，例如"样本不独立、违反残差独立性 → 需要混合模型"，先讲为什么，再讲怎么做。
- piecewiseSEM 与混合模型结合：子模型可以带随机效应、用非正态响应。

**要避开**

- 营销式标题（"溜到飞起""火力全开"）和密集的课程广告。
- 可见摘要建议"高维数据先用随机森林筛选变量，再做线性回归"。按统计常识补充：如果用同一份数据先筛变量、再检验 P 值，P 值会偏乐观（选择偏倚）。Skill 不默认这样做；用户坚持时，要提醒并建议嵌套交叉验证或独立数据检验。

**证据强度**：很弱（5 个标题）。

### 红皇后学术（v3.0 新增）：微生物组 R 教程

**可吸收**

- 距离选择写明理由：物种组成用 Bray-Curtis，环境因子标准化后用欧氏距离（如 Procrustes 分析中）。
- PCA、PCoA、NMDS 等教程的代码模块可以组合复用。
- 作者对早期旧笔记有重新整理、修订的意识。

**要避开**

- "回复关键词领取示例文件"导致正文代码不全、无法复现。
- 以"完美重现 STAMP 结果图"为目标却不说明检验方法与校正方式是否一致。
- 内容整体偏早（可见内容疑似 2019–2020 年），不吸收其中可能过时的默认做法，例如把稀释均一化当作默认步骤。

**证据强度**：很弱。可见标题无日期，且其中有整理"小白鱼"笔记的合集，部分内容可能与小白鱼重叠。

### 小田的生信随笔（v3.0 新增）：面向毕业论文的作图与基础统计

**可吸收**

- 受众最贴近本 Skill：写毕业论文的土壤、农学、微生物方向研究生。内容按论文章节需要组织，如 RDA 图、相关性热图、采样点图。
- 示例数据明确声明是模拟的，避免读者把示例结果当真。
- 批量处理多个变量（批量方差分析、批量箱线图）并导出结果，是农学和土壤论文的高频需求。按统计常识补充：批量检验时要对每个变量分别检查前提，并说明跨变量的多重检验是否校正。

**要避开**

- 脚本开头默认写 `rm(list = ls())`。它只清空变量，不会重置已加载的包和选项，并不能保证可复现，还会删掉用户环境里的其他对象。
- 只用多重比较字母代替效应量和置信区间。
- 默认用 LSD 或 Duncan 法给显著性字母，而不说明它们控制 I 类错误较宽松。

**证据强度**：弱（12 个标题，系列清晰）。

## 跨账号共识：吸收进 Skill 的做法

多个号的可见内容里反复出现、且统计上站得住的做法：

1. 以研究问题或论文图为起点组织代码，复现时点明原文图号和方法。
2. 示例数据自包含：固定随机种子，写明是模拟数据或使用的公开数据集。
3. 先讲前提和"为什么用这个方法"，再给代码。
4. 变量重要性和方差分解讲清各自回答什么问题，不混用、不写成因果。
5. 图与模型一致：模型图用模型预测值，统计标记写明来自哪个检验。
6. 系列化：复杂分析分步讲，前后衔接清楚。
7. 常见坑单独提醒：长宽转换、因子顺序默认按字母排、读 Excel 后数值变成字符等。

## 共同糟粕：Skill 明确不学的写法

1. 标题党与夸张形容词："绝美""神图""一键出图""溜到飞起""Nature 同款"。
2. 残缺代码引流："回复关键词获取完整代码""关注后领取"。Skill 给出的代码必须完整可运行。
3. 课程营销与技术内容混编。
4. 只追求形似的复刻：只给图、不给统计依据；用外部软件收尾导致不可复现。
5. 脚本开头默认 `rm(list = ls())`。
6. 未经检查的批量检验：不检查前提、不说明多重检验校正。
7. "先用同一份数据筛变量，再报告显著性"而不提选择偏倚。
8. AI 生成的复杂模型代码（SEM、混合模型、Meta）不运行、不核对就交付。

## 近一年的新动向（仅作参考，不作为写法来源）

目标账号的可见内容里能确认的新信号有：AI 辅助写分析代码、glmm.hp 的新功能（交互项贡献等）、piecewiseSEM 的版本更新、树模型加 SHAP 解释。shapviz、linkET 等包在中文 R 圈很热门，但这次只在其他账号里大量出现，不能算作这些目标账号的写法；ggplot2 4.x、tidyplots、brms、Hmsc 等也没有在目标账号的可见内容里出现。Skill 涉及这些包时，按包本身的文档写，不以"公众号流行"为依据。
