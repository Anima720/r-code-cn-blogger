# r-code-cn-blogger

**把 AI 生成的 R 代码，从“能跑”变成“科研人员真的敢用”。**

`r-code-cn-blogger` 是一个面向中文科研用户的 R 代码生成与修改 Skill。它专门约束 AI 在生态学、农业科学、微生物生态、生物统计和科研绘图场景下的代码写法，让输出更接近一份真正可交给实验室同学使用、可以复现、能够检查、知道哪里该改也知道哪里不能乱改的科研脚本。

它不是简单地“多写中文注释”。它重点解决的是另一类更常见的问题：

- AI 给出的 R 代码语法没问题，但用户不知道每一步为什么这样做；
- 为了让代码看起来更完整，AI 擅自标准化、删 NA、做 log 转换或改显著性校正；
- 随机森林的拟合度、预测性能和变量重要性被混在一起解释；
- RDA、CCA、PCoA、NMDS、Mantel、PERMANOVA 等生态统计方法被概念混用；
- SEM 只剩下 `psem()` 和漂亮箭头，却没人告诉你 Fisher's C、d-sep 和路径系数到底怎么看；
- 用户只要求“换一个变量名”，AI 却顺手把整套分析逻辑重构了。

这个 Skill 的目标，是让 AI 更像一个真正做过科研数据分析的人在整理自己的脚本，而不是像一个代码补全器。

## 适用场景

特别适合：

- 生态学与群落生态分析
- 农业与土壤科学数据分析
- 微生物生态
- PCA / PCoA / NMDS / RDA / CCA
- Mantel / Partial Mantel / PERMANOVA
- variation partitioning / 层次分割
- 随机森林与变量重要性
- 混合效应模型与重复测量
- piecewise SEM / 结构方程模型
- 贝叶斯模型
- Meta-analysis 后续回归或机器学习
- ggplot2 科研绘图
- 论文 R 代码摘取、复现和最小改动
- R 报错排查

## 核心原则

Skill 在发生冲突时遵循以下优先级：

1. 用户明确要求
2. 用户原有分析逻辑和研究设计
3. 统计与数学正确性
4. 从上到下能运行
5. 结果可复现、可核查
6. 代码容易理解和修改
7. 中文科研教程式表达
8. 代码形式上的漂亮和简洁

也就是说，**“更现代”“更优雅”“更短”永远不能成为偷偷改变统计方法的理由。**

## 它会主动做什么

例如，生成完整科研脚本时，它倾向于：

```r
# 三、数据预处理 ------------------------------------------------------------

# 注意：下面的列名必须与 Excel 第一行完全一致，包括大小写

# ★ 如果你的处理名称不同，只修改下面这个向量即可

# 这里之所以这样处理，是因为……

# 结果怎么看：重点查看……
```

但不会把每一行 R 语法机械翻译成中文。

它还会尽量避免下面这些典型“AI 味”操作：

```r
install.packages("xxx")   # 每次运行都自动安装

df <- na.omit(df)         # 不解释就删除缺失样本

df <- scale(df)           # 整张表直接标准化

# Pearson 不显著，自动换 Spearman

# 原始 P 不显著，自动改 BH 或筛掉路径
```

## 一个完整示例：piecewise SEM

仓库中提供了一份可以直接运行的结构方程模型示例：

[`examples/piecewise_sem_example.R`](examples/piecewise_sem_example.R)

场景设定为玉米农田中的：

```text
SOC / SWC
   ↓
  MBN
   ↓
Mineral N
   ↓
  Pn
   ↓
 Yield
```

示例代码不是只给 `psem()`，而是完整包含：

- 模拟数据
- 输入变量检查
- 缺失值检查
- 每个 SEM 子模型的生态含义
- `psem()` 模型组合
- Fisher's C
- d-separation
- 标准化路径系数
- 各内生变量 R²
- 指定间接效应计算
- 路径图
- CSV 结果导出
- 对因果解释边界的中文提醒

## 文件结构

```text
r-code-cn-blogger/
├── SKILL.md                       # 主文件：所有任务都适用的规矩（约 650 行）
├── references/                    # 按需加载的参考文件，遇到具体任务才读
│   ├── data-and-script.md         #   包管理、排版、读数据、检查、转换、缺失值、输出、版本变化
│   ├── ecology-stats.md           #   排序分析、PERMANOVA、Mantel、方差分解、随机森林、SEM 等
│   ├── plotting.md                #   ggplot2（含 4.x 写法变化）、保存、显著性标记
│   ├── troubleshooting.md         #   报错排查
│   ├── examples.md                #   合格/不合格代码对照、RDA 完整模板
│   └── style-sources.md           #   11 个公众号的风格画像：吸收了什么、避开了什么
├── examples/
│   └── piecewise_sem_example.R    # 可直接运行的 piecewise SEM 完整示例
├── CHANGELOG.md
├── README.md
└── LICENSE
```

v2 把 2000 多行规则全部放在一个 `SKILL.md` 里，每次调用都要整份读入。v3 按当前 Agent Skills 的做法拆成"主文件 + 按需加载的参考文件"：主文件只放通用规矩，做 RDA 才读排序分析那一份，画图才读绘图那一份，省 token，也更不容易顾此失彼。

这个 Skill 不逐字模仿任何公众号作者，而是提炼中文生态学、生物统计和科研绘图类教程中反复出现、对代码质量真正有帮助的共同写法，取其精华、去其糟粕。

参考的公众号：

- Datasphere探索
- 小白鱼的生统笔记
- R语言生态小白
- 藻类生态学与R分析作图
- 植物功能生态
- 二傻统计（v3.0 新增）
- 红皇后学术（v3.0 新增）
- 小田的生信随笔（v3.0 新增）

**关于证据的说明**：v3.0 通过搜狗微信搜索重新检索了这些账号，但微信原文无法批量读取，这一轮只看到了推文标题和摘要，没有读到正文，也无法核实发布日期。另一个计划新增的"地上地下生态学"没有检索到，暂未纳入。所以各账号画像写的是写法倾向，并为每个号标了证据强度；所有统计规则都以统计学本身为依据。欢迎提供推文链接帮助完善。

重点吸收的是方法落地、矩阵意识、参数解释、统计前提、结果怎么看、易错点提醒和论文复现导向；明确不学的是标题党、"一键出神图"、不解释就删 NA 或标准化、P 值不显著就换方法、付费墙式残缺代码。每个账号的画像见 [`references/style-sources.md`](references/style-sources.md)。

## 推荐的使用方式

你可以直接要求 AI：

```text
请使用 r-code-cn-blogger 风格生成这段 R 分析代码。
要求从读取数据到结果导出完整可运行，并在容易出错的位置用中文提醒。
不要擅自改变我的统计方法。
```

或者更具体：

```text
我有一个 Excel 数据表，CFSI 为因变量，其余变量为解释变量。
请按照 r-code-cn-blogger 的规范生成随机森林分析代码。
随机森林 1000 棵树，rfPermute 置换 1000 次，原始 P 值，不做 BH 校正。
```

对于已有代码，推荐明确写：

```text
只修改输入变量和文件读取部分，其他统计分析逻辑全部保持不变。
```

Skill 会把这种要求视为需要保护的“分析协议”。

## v3.0 有什么不同

- **结构**：拆成主文件 + 6 个按需加载的参考文件，适配当前各家模型的 Agent Skills 机制。
- **面向新一代模型的约束**：能运行就真的运行，没运行要如实说；不凭记忆编函数和参数；从结果对象取值后验证不是空值；不编造结果；小改动不输出整份脚本；长对话里守住"不要动"的分析协议；不覆盖用户原始数据。
- **R 包更新**：按 vegan 2.7（`adonis2()` 默认 `by = NULL`、取排序得分改用 `scores()`）、ggplot2 4.x（`linewidth`、`legend.position = "inside"` 等）、piecewiseSEM 2.3 更新了规范和模板。
- **修正示例中的真实错误**：v2 的 SEM 示例用 `sem_summary$CStat` 提取 Fisher's C，元素名大小写不对，R 不报错但返回空值，导出的是空文件。v3 改用 `fisherC()`，并加了提取后的检查。
- **风格来源**：新增 3 个公众号，按检索到的推文标题和摘要重写各账号画像，逐个标注证据强度；吸收了混合模型诊断、几类变量重要性方法的区分、SEM 与 Meta 分析扩写、批量方差分析、树模型评估与 SHAP、示例数据规范等内容。

完整变更见 [`CHANGELOG.md`](CHANGELOG.md)。

## 设计理念

一份好的科研 R 代码，不应该只满足“RStudio 没报错”。

它还应该让一个懂科研问题、但 R 水平一般的人能够知道：

- 数据应该是什么结构
- 哪些地方必须按自己的数据修改
- 哪些参数不能随便动
- 某一步为什么存在
- 当前输出到底代表什么
- 哪些结果不能被过度解释
- 如果报错，第一步该检查哪里

最终目标只有一句话：

> 不是“AI 把 R 语法拼出来了”，而是“一个懂这项分析的人，把代码整理成别人真的能用的科研脚本”。
